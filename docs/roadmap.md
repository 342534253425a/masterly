# Дорожная карта

> Сначала узкая ниша (ремонт смартфонов в трёх городах) с отличным качеством, затем расширение по данным:
> новые категории и города добавляются там, где спрос виден в отчёте о пробелах каталога.

## Этап 0 — фундамент ✅

- Монорепозиторий, контракты (zod → OpenAPI), Protobuf-схемы сервисов и событий.
- Веб-приложение: 34 маршрута для клиента, мастера и администратора, работает в демо-режиме на моках из
  контрактов. Storybook, e2e-тесты.
- Инфраструктура: Docker Compose (весь стек локально), Helm-чарт сервисов, Terraform для Yandex Cloud,
  CI/CD с подписью образов, k6-профили, архитектурная документация и ADR.

## Этап 1 — MVP: ремонт смартфонов, Москва / Санкт-Петербург / Краснодар

**Продукт:**
- поиск по проблеме, услуге и модели устройства, фильтры, сортировка, карта;
- профили мастеров с ценами, сроками, гарантией и контактами, сравнение;
- прямой контакт и простые заявки, базовые отзывы (только по завершённым заявкам) и верификация;
- кабинет мастера: профиль, цены, модели, расписание, заявки, отзывы, статистика, команда и филиалы;
- админ-панель: каталог услуг, модерация, дубликаты, пробелы каталога, средние цены.

**Платформа:**
- доменные сервисы identity, catalog, search, leads, reviews, messaging, notifications, media, analytics, trust;
- шлюз;
- outbox/inbox, SLO-алерты, ранбуки.

**Сделано:** платформа, 10 доменных сервисов и шлюз, сквозной тест проходит весь путь заявки через HTTP.

**Этап 1.1 — сделано:** все маршруты живого режима подключены к сервисам; живая доставка чата по WebSocket
(`:8081`, Redis Pub/Sub между подами); провайдеры доставки — SMTP, SMS-шлюз, Web Push (VAPID).

**До запуска:**
- ключи VAPID и SMTP Postbox в Lockbox; домен отправителя с SPF/DKIM/DMARC;
- Telegram-бот как канал уведомлений (привязка чата по deep-link);
- список отозванных access-токенов в Redis, чтобы блокировка действовала мгновенно, а не через ≤15 минут;
- шардированный Pub/Sub (`SPUBLISH`, Valkey 7+) при росте за ~200 тыс. одновременных соединений.

**Критерии запуска:**
- нагрузочный прогон 25 000 RPS на боевой инфраструктуре в SLO;
- учения по отказу зоны;
- ревью безопасности, документы по 152-ФЗ;
- не меньше 300 проверенных мастеров на город.

## Этап 2 — умный подбор и запись

- **Интеллектуальный подбор.** Обучаемое ранжирование (learning-to-rank) на кликах, контактах и заявках;
  персонализация только при согласии. Офлайн-оценка nDCG и A/B-тесты.
- **Календарь записи.** Слоты мастера, подтверждение, напоминания с учётом тихих часов, перенос и отмена.
- **Расширенная аналитика для мастеров.** Спрос по районам и моделям, сравнение цен с рынком, когорты клиентов.
- **Passkeys для клиентов, канареечные выкладки** (Argo Rollouts), непрерывное профилирование.

## Этап 3 — монетизация и рост

- **Подписка Pro** по внешним счетам: расширенная статистика, больше фото, филиалы, приоритетная поддержка.
- **Продвижение:** маркированные рекламные слоты (erid, отчётность в ОРД), отдельная статистика показов.
- **Оплата за качественные заявки** — если пилот подтвердит ценность (прозрачная отчётность в кабинете).
- **Новые категории** (ноутбуки, бытовая техника, электроника) и города — по данным о спросе.
- **Локализация** EN и ZH (интерфейс уже на next-intl, цены в рублях).
- **Тёплый резерв в другой площадке РФ** (RTO ≤ 1 ч).

## Этап 4 — масштаб

- Шардирование leads и messaging, cell-архитектура по группам городов.
- ML-антифрод: графовые признаки накруток и сетей дубликатов.
- Публичный партнёрский API (OpenAPI уже генерируется) для сетей сервисных центров.

## Сознательно не делаем

| Чего нет | Почему |
|---|---|
| Онлайн-оплаты и платёжного интерфейса | Требование продукта; оплата только по внешним счетам ([ADR-0009](adr/0009-no-payments.md)) |
| Комиссии с ремонта | Платформа не стоит между клиентом и мастером в расчётах |
| Скрытого трекинга, сторонних пикселей, продажи данных | Приватность — часть продукта ([security-privacy.md](architecture/security-privacy.md)) |
| Рекламы, замаскированной под органическую выдачу | Доверие к выдаче важнее краткосрочной выручки |
